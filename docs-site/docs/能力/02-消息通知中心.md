# ② 消息 / 通知中心（ruoyi-message）

## 是什么

通用**站内通知** + **私信会话**中心。去业务耦合：通知的关联对象统一用 `biz_type(varchar) + biz_id(bigint)` 挂载点，不写死 orderId / petId。5/5 参考项目都各造过一遍。

## 在哪

后端 `RuoYi-Vue-Plus/ruoyi-modules/ruoyi-message`（包 `org.dromara.message`）：

- **`NotificationHelper.send(...)`** —— 核心复用点，任意业务触发点一行调用。
- 表 `app_notification`（系统通知/未读）、`app_message`（私信，扁平存储、会话按无序对 (from,to) 归并）。建表 SQL 在 `ruoyi-message/src/main/resources/sql/`。
- C 端 `/app/notice/*`（列表 / 未读数 / 标已读 / 全部已读）、`/app/message/*`（会话列表 / 会话消息分页 / 发送 / 未读数），全部 `AppLoginHelper.getUserId()` 强制归属防越权。
- 管理端 `NotificationController`（`/message/notification/*`）。
- 前端：uni-app `pages/message/{notice,conversations,chat}.vue` + `api/message.ts`；plus-ui `views/message/notification/`。

## 怎么用

业务里任意触发点发一条通知：

```java
NotificationHelper.send(receiverId, "订单已发货", "您的订单#1001已发货", "order", 1001L);
```

两大保证：

- **静默容错**：全程 try/catch，异常只 `log.warn`，绝不外抛、绝不破坏调用方主流程；`receiverId==null` 静默跳过。
- **不污染主事务**：底层 `INotificationService.send` 用 `REQUIRES_NEW` 独立事务落库。

!!! warning "一致性权衡"
    `REQUIRES_NEW` 下，若主业务随后回滚，通知仍留存。需强一致就在**业务提交后**再 `send`。

## 数据约定

- 越权防护：C 端读写都以 `getUserId()` 作过滤/CAS 条件（标记已读 `where id=? and receiver_id=me`；chat 只拉与自己相关消息）。
- 无需改 `security.excludes`：`/app/notice/*`、`/app/message/*` 走安全拦截器鉴权（同 getInfo）。
- 私信不建 conversation 表（YAGNI），会话由 (from,to) 归并。

## 验证（已通过）

- 私信 A→B：未读=1 → 会话列表（对端昵称/最后消息/未读）→ 进入 chat 自动清未读 → 未读=0。
- 通知：写入 → 列表 → 未读=1 → 标已读 → 未读=0。
- `NotificationHelper.send` 真实发送链路由回归测试 `WalletEngineVerifyTest` 覆盖（发送→未读+1→标已读→还原）。
- 全 reactor `mvn compile` + uni-app `build:h5` 通过。
