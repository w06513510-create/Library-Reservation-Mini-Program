# ⑤~⑧ 脚手架 / 代码模板

## 是什么

业务耦合较高、不适合做成运行时模块的能力，做成**"复制即用"代码模板 + 文档**（DDL + Java 骨架 + 前端片段 + README）。新项目按需复制到自己的业务模块改造。

位置：`docs/templates/`（索引见 `docs/templates/README.md`）。命名占位包名 `org.dromara.<biz>`，复制后全局替换成你的业务名；风格对齐 `ruoyi-app`（`BaseMapperPlus` / `@AutoMapper` / `PageQuery`/`TableDataInfo` / `LoginHelper`）。

## 四套模板

| # | 模板目录 | 用途 | 关键文件 |
|---|---|---|---|
| ⑤ | `docs/templates/audit-state-machine/` | 通用审核单："提交→待审→通过/驳回(带理由)" + 流转日志 + 审核后回调钩子 | `BizAuditServiceImpl`（状态机）、`AuditCallback`（按 bizType 回调）、`biz_audit.sql` |
| ⑥ | `docs/templates/dashboard/` | `/overview` 一次性聚合下发 KPI 卡片 + echarts 多图 | `BizDashboardMapper.xml`（聚合 SQL 范式）、`index.vue`（卡片+4图） |
| ⑦ | `docs/templates/survey-engine/` | 一套表覆盖考试(有答案+自动评分)/调查(匿名+统计)/问卷 | `SurveyScoreUtils`（客观题判分）、`survey.sql`、`objective`/`anonymous` 开关 |
| ⑧ | `docs/templates/rating/` | 1-5 星评价，可双向；一单一评唯一约束 | `rating.sql`（`uk_biz_role`）、`RatingPartyResolver`（服务端定向）、`StarRate.vue` |

## 怎么用（通用步骤）

1. 建表：执行模板 `ddl/*.sql`（表名前缀换成你的业务）。
2. 落 Java：复制 `java/` 到 `ruoyi-modules/ruoyi-<biz>/.../org/dromara/<biz>/`，全局替换占位（包名/类名/表名/权限串）。
3. 前端：`vue/` / `uni-app/` 片段按注释放到 `plus-ui` / `uni-app`。
4. 接线：模块 pom 抄 `ruoyi-demo`，`ruoyi-modules/pom.xml` 加模块，`ruoyi-admin/pom.xml` 加依赖；mapper XML 放到被扫描的 `resources/mapper/<biz>/`。
5. 配菜单/权限：`sys_menu` 配菜单与按钮权限。

!!! note "落地时要手写的业务耦合点"
    ⑤ 的 `AuditCallback`（审核后副作用）、⑧ 的 `RatingPartyResolver`（评价方向解析）、⑥ 聚合 SQL 里换表名列名。

## 落地顺序建议

⑦ 问卷引擎（宿舍曾抄 3 份，ROI 最高）→ ⑤ 审核状态机（几乎每个业务都要审批）→ ⑥ 看板 / ⑧ 评价（按需）。

!!! warning "不编译"
    这批模板放在 `docs/` 下、在 Maven 构建之外，**不参与编译**；复制进真实业务模块后才编译。质量靠 review 保证。
