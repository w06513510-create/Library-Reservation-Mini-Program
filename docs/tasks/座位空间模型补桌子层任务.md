# 任务 · 座位空间模型补「桌子（工位组）」层

> 目标：把座位空间模型从「阅览室 → 座位」两级，改为**「阅览室/区域 → 桌子(工位组，带容量与坐标) → 座位」三级**，让平面图能呈现「**一张桌子展开 N 个可独立预约座位**」的真实效果。
> 状态：**待做**（需求/模型缺口，本任务未开始）。属库结构改动，牵动 schema + 种子 + 平面图前端。

## 一、为什么要改（问题）

现状 `biz_seat` 直接挂在区域/楼层下，**没有「桌子」这一层**；平面图选座（`seatmap`）里每个座位是一个孤立方块（**一位一座**）。但真实高校自习室常是**一张桌子坐 4/6 人**——清华图书馆就有单/双/四人桌/吧桌多种桌型，南开的座位标签贴在**阅览桌正上方**。现实里天然成组的"桌—座"被拍平成单体，导致：

- 平面图做不出"一桌多座成组、点其中一个空座预约"的核心亮点；
- 无法表达桌子容量/形状/朝向，也无法按桌子布局排布座位。

依据见 SOP [`01 需求` §二.1「真实的物理/领域结构与粒度」](../../../SOP/docs/01-需求.md) 与 `specs/research-notes.md §1.4`（真实层级 + 建模建议 + 来源：清华/南开/超星/LibCal）。

## 二、目标模型（三级）

```
biz_area(阅览室/区域)
  └─ biz_desk(桌子/工位组)  新增：area_id, desk_no, capacity(1/2/4/6), shape(rect/round/bar),
                            pos_x, pos_y, width, height, rotation   ← 平面图坐标
       └─ biz_seat(座位)     改：加 desk_id(外键桌子) + offset_x/offset_y(相对桌子偏移)；
                            seat 数应 = 桌子 capacity
```

- 坐标推荐：**桌子存绝对坐标 + 座位存相对桌子的偏移**（配桌子时座位自动成组排布，改桌位不用逐座改）。
- `seat_code` 复合可读码（如 `F3A020`=3 楼 A 区 20 号）；桌号 `desk_no` 单独留，便于"扫桌上二维码→定位到桌→列该桌空座"。
- **状态分离**：座位静态属性（停用/维修）与运行态（占用/空闲）分开——运行态由 `biz_reservation` 实时算，`biz_seat` 只存是否停用。

## 三、待改动清单

1. **库**：新增 `biz_desk` 表；`biz_seat` 加 `desk_id` + `offset_x/offset_y`（保留 `pos_x/pos_y` 兼容或迁移）。同步 `sql/schema.sql`、数据库设计说明书。
2. **后端**：`Desk` 全栈 CRUD（照参考模块）；`seatStatus` 接口按桌分组返回（桌 + 桌下座位状态）；**约座仍以 `seat` 为最小可预约单元**，并发行锁/时段重叠逻辑不变。
3. **前端 `seatmap`**：渲染桌子（矩形/圆/吧台）+ 桌上成组座位；点空座预约；缩放/图例沿用。
4. **演示数据**：把现有 20 个孤立座位重排为「若干桌 × 每桌 N 座」（如 5 桌四人桌 = 20 座）。
5. **校验**：平面图上一张四人桌展开 4 个可独立预约座位、坐标成组；大屏座位计数口径不变；约座并发保护仍生效。

## 四、影响面与边界

- 影响：`schema.sql` / 座位与桌子种子 / `seatmap` 前端 / 座位相关 VO；**不影响**信用、借阅、违约等其它域。
- 边界：本任务只做「空间结构」；预约规则参数（签到窗口/暂离/就餐保留/封禁）是另一件事，见同目录 [`座位管理规则梳理任务.md`](座位管理规则梳理任务.md)。
